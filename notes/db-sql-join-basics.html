SQL 關聯查詢（INNER JOIN 與 LEFT JOIN）實務

透過資料表關聯範例比較交集查詢與左外部聯結的差異，學會正確處理 NULL 值與避免資料列倍增。

1. 核心觀念說明

在關聯式資料庫（如 MySQL、PostgreSQL）中，為了避免資料重複儲存，我們會將不同主題拆分成多張資料表，並透過主鍵（Primary Key）與外來鍵（Foreign Key）建立關聯：

  • INNER JOIN（內部聯結 / 交集）：只會回傳左右兩張資料表中，ON 關聯條件完全符合的資料列；任何一邊找不到對應紀錄的資料都會被排除。
  • LEFT JOIN（左外部聯結）：以 FROM 後方的左表為主，保留左表的所有資料列；若右表沒有符合的關聯紀錄，右表欄位會自動以 NULL 填補。
  • 查詢未關聯資料的技巧：結合 LEFT JOIN 與 WHERE 右表.主鍵 IS NULL，可快速找出「尚未選課的學生」或「尚無訂單的會員」。

2. 程式碼範例與解說

假設有學生資料表 Students (student_id, name) 與選課紀錄表 Enrollments (enroll_id, student_id, course_name)：

SQL 
-- 範例 1：INNER JOIN（只列出「有選課」的學生與課程名稱）
SELECT
    s.student_id,
    s.name,
    e.course_name
FROM Students AS s
INNER JOIN Enrollments AS e
    ON s.student_id = e.student_id;

-- 範例 2：LEFT JOIN（列出「所有學生」，未選課者課程欄位顯示為 NULL）
SELECT
    s.student_id,
    s.name,
    COALESCE(e.course_name, '尚未選課') AS course_status
FROM Students AS s
LEFT JOIN Enrollments AS e
    ON s.student_id = e.student_id;

-- 範例 3：找出「完全沒有選修任何課程」的學生名單
SELECT
    s.student_id,
    s.name
FROM Students AS s
LEFT JOIN Enrollments AS e
    ON s.student_id = e.student_id
WHERE e.enroll_id IS NULL;
  • 資料表別名（Alias）：使用 Students AS s 與 Enrollments AS e 縮短查詢語句，並明確標示欄位來源（如 s.student_id）。
  • COALESCE() 函式：在範例 2 中將原本顯示為 NULL 的欄位轉換成可讀性更高的提示文字 '尚未選課'。

3. 常見錯誤與注意事項

⚠️ 除錯與語法提醒
  • 在 LEFT JOIN 後用 WHERE 過濾右表欄位：若寫成 LEFT JOIN Enrollments e ON ... WHERE e.course_name = '資料庫系統'，原本右表為 NULL 的資料列會全部被 WHERE 濾掉，導致 LEFT JOIN 退化成 INNER JOIN。若要保留左表全部資料，應把右表過濾條件放進 ON 子句中。
  • 欄位名稱模糊（Ambiguous Column Name）：兩張表都有 student_id 時，若在 SELECT 只寫 student_id 而不加別名前綴（s.student_id），資料庫會直接報錯。
  • 一對多關聯導致資料列倍增：若一位學生選了 3 門課，JOIN 後該名學生會出現 3 列；此時若直接用 COUNT(*) 計算學生人數會重複計算，應改用 COUNT(DISTINCT s.student_id)。
